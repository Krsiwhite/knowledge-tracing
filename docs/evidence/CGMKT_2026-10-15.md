# CGMKT：本阶段可训练性与因果边界

2026-10-15。只读官方页面、论文公开摘要及本地固定源码；未读取真实学生数据、图产物或保存预测，未导入模型、运行前向、梯度、优化器或 GPU 验证。本文不改变现有批次、源码或数据清单。

**结论：CGMKT 值得保留为显式状态方向的强相关候选，但现在不能标记为“三个主数据集可训练基线”，也不宜直接追加真实训练。** AS09/NIPS34 有源码映射和官方训练入口；图、分组和文本向量的生成范围尚未闭环。AS15 没有独立题号，固定实现没有对应分支，不能用统一 dummy 题号声称忠实接入。建议先取得并审计作者预处理 notebook 和产物来源，再做 NIPS34 的小规模兼容性接入，之后考虑 AS09；AS15 留作明确不支持，或另立方法变体。

| --- | --- |
| `ques_skill_gcn_adj.pt` | 题目 GCN 的邻接。虽然文件名像 question–skill，实际乘的是 `[Q,d]` 题目参数，应为 `[Q,Q]`；不能直接塞 `[Q,C]` incidence。官方论文摘要也区分由 incidence 导出的题目共现图与 incidence 本身 |

| `sbm/` 下 block 候选文件 | `[K,K]` 分组关系，转成去对角、行归一的 `group_transition` |

来源：[cgmkt.py L33–37、L52–124、L184–232、L282–329](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/pykt/models/cgmkt.py#L282)、[Questions_Embedding L123–181](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/pykt/models/QueGraphLearing.py#L123)、[Concepts_Embedding L119–175](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/pykt/models/SkillGraphLearning.py#L119)。

两处不能静默处理：

1. **缺少 membership 不会停止初始化。** `cgmkt.py L293–295` 会将 KC 邻接转 dense、对称归一、`torch.linalg.eigh` 后做简易 k-means（L127–163）。缺 block 则按 membership 聚合 KC 邻接（L299–303）。这是可运行 fallback，不能无条件称为作者原始 SBM 拟合产物。正式基线应记录每个实际采用文件或 fallback 身份；欲忠实复现应拒绝未声明 fallback。
2. `Q_hat` 与 `group_transition` 是 buffer；端到端训练的是 `raw_spread_rate` 及更新网络等参数，不能把 transition 误报为每个 minibatch 中参与梯度更新的自由矩阵（L297、315、321）。外部 SBM 可以离线学习结构；这与“结构来自学习”并不矛盾。

路径还有实际工程障碍：主模型从当前工作目录下 `../data/<dataset>` 读图，而两个图模块从自身 pyKT 根目录的 `data/<dataset>` 读向量和 map（各自 L11–26）。`emb_path` 构造参数没有用于这些路径。仓库 vendor 排除了 `data/`，不能假设本项目 `data/prepared/` 自动被找到。后续应在隔离 wrapper/worker 中明确绑定同一套只读资产根并记录哈希，保留 vendor 字节；不能只给 `SUPPORTED_MODELS` 加一个名称就宣称接入完成。

## 图与统计是否仅来自训练 fold

**目前只能证明训练样本按 fold 隔离，不能证明图和文本资产按 fold 隔离。**

- `init_dataset.py L200–205` 以 `{i}` 选验证、`all_folds-{i}` 选训练；`KTQueDataset` 在 L123–124 按 fold 过滤。这是运行时序列分割证据。[init_dataset](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/pykt/datasets/init_dataset.py#L200)
- 图、membership、block、map、向量的加载接口没有 `fold`，路径只含 dataset 和 group 数；当前固定模型也没有生成者、源事件哈希、学生集合或 split 收据。[cgmkt.py L282–305](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/pykt/models/cgmkt.py#L282)
- 所以不能从“模型读取了一个全局图”直接认定泄漏，也不能从“训练 loader 排除了验证 fold”反推图已经安全。若题目图只由预先可用题目–KC 元数据构建，它可能是明确声明的静态目录信息；若 KC 依赖、SBM 输入、边权或文本统计使用了验证/测试作答，则须另核是否越过当前评测边界。

必须补齐的最小来源链：notebook 固定字节与依赖；原始 KC 文本/题目–KC schema 的来源及可用时点；Q/C 编号映射；训练学生与 fold 清单；图边生成是否读 response/正确率/时序共现；归一化、SBM 拟合和超参选择用到哪些记录；每个最终文件的 SHA、形状、dtype、nnz、创建参数。若采用只用训练 fold 重建的方案，应称本项目的受控图构建轨，并如实说明与未经核实的官方产物范围可能不同，不能悄悄替换后沿用论文成绩。

## 前向响应依赖与共同事件评测

官方调用为 `model(q, r, c, qshft, cshft)`，返回 `(y, zero_scalar)`；训练对 `y[smasks]` 和 `rshft[smasks]` 做 float64 BCE，不额外加入返回的零项。`train_model.py L336–337` 对 CGMKT 使用梯度裁剪 15。评测使用相同五字段调用。[train forward L216–218](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/pykt/models/train_model.py#L216)、[loss L55–59](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/pykt/models/train_model.py#L55)、[evaluate L127–129](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/pykt/models/evaluate_model.py#L127)。

输入必须保留题目事件：q/r 为 `[B,T-1]`，c 为 `[B,T-1,max_concepts]`，next q/c 是对应右移序列。模型一处注释允许 2D concepts，但实际 `SkillGraphLearning.get_kc_embedding` 在 L64 解包三个维度，不能据那段注释改成普通 repeated-KC 二维 loader。KTQueDataset 用下划线分隔同题 KC、填充 -1，q/r 的无效 pair 被 mask 置0；CGMKT 不需要 timestamp、耗时或 MoC 的 ground_seq。[loader L75–94、L128–161](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/pykt/datasets/que_data_loader.py#L75)

固定前向的实际顺序是：

1. 由题目图/KC 图得到静态节点表示，历史表示加上历史回答 embedding；next 表示只取下一题与下一题 KC，没有下一题回答。
2. 每次 forward 把 GRU hidden 与 group mastery 清零（L449–451）。按 t 从左到右，用先前 mastery 调制第 t 次已知历史交互，再执行 GRU；用已知 `last_ans[:,t]` 更新 mastery（L455–464）。
3. 将处理完历史 t 的 hidden/mastery 与 next q/KC 合成 `y[:,t]`，预测 t+1。`rshft` 只进入外部监督损失，不作为模型输入（L466–473）。

因此，**在固定且合规的图资产、正确单次 shift 下，静态代码未发现当前待预测回答或更晚回答进入其预测的通路**。不能把“更新使用 r_t”直接叫泄漏：此处对应预测 r_{t+1}。next q/KC 是允许的当前查询，之后的 query 只进行逐位置查表和读出，没有跨时间聚合回早期 hidden。[完整 forward L430–473](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/pykt/models/cgmkt.py#L430)

这仍不是动态因果验收：模型仅在无效步阻止 mastery 更新，GRU hidden 仍更新（L458–461）。连续有效前缀之后的右 padding 不会反向影响较早输出，但左 padding、内部空洞和后续有效位置不保证不变。wrapper 必须沿用完整左对齐历史、右 padding，并只评分真实目标。

接入现有 v2 时，可以把**完全相同的完整历史事件与当前 query**组成最多200事件的序列，再形成199个 shifted pairs，取 `y[:,history_event_count-1]`。该位置已消费全部允许历史，却未消费当前 query 的回答；query 的真实 label 只留给外部指标。同题多 KC 应在同一事件内 mean pooling/分组聚合一次，不能像概念级模型那样重复更新，也无需对本身题目级输出再做 KC late mean。单个目标重放必须重新清零状态，不能跨其 KC200 允许窗口带入更早状态。

## 依赖、默认配置与资源判断

核心只依赖 PyTorch、NumPy，以及两个图模块顶层导入的 pandas；没有看到核心需要 Mamba、PyG、DGL、外部图采样 CUDA kernel。图运算为 `torch.sparse.mm`，SBM 产物拟合依赖及 BGE 编码依赖因 notebook 未取得而未知。不能用“核心不依赖 Mamba”推导已在本机 ROCm 兼容。

官方入口默认 AS09、seed3407、embedding256、dropout0.3、题图 dropout0.05、KC图 dropout0.4、K=4、GCN1层、mastery update hidden64、step0.1、gate、SBM spread、batch128、200epochs、lr1e-3；`wandb_train.py` 将 CGMKT 分到 Adam weight_decay1e-5 分支。**这些是脚本默认，不是三集最佳超参；200epoch 也不能覆盖本项目最多50epoch/patience3 的现行预算。** [入口 L15–40](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/examples/wandb_cgmkt_train.py#L15)、[optimizer L147–154](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/examples/wandb_train.py#L147)

固定 sweep 搜索 d∈{64,128,256}、lr∈{1e-3,5e-4,2e-3,1e-4}、K=2..10 等，但其 dataset=`xes`、emb_type=`qid_py_randkcg`，而核心 `py` 会映射 peiyou、并没有读取 `randkcg` 来切换图。这份配置不能当作 AS09/AS15/NIPS34 的已核实调优方案。[sweep](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/examples/seedwandb/cgmkt.yaml)

以下仅为形状算术，**不是峰值显存、实测耗时或训练可完成承诺**：

| 项 | AS09 Q=17,737 | NIPS34 Q=948 |
| --- | ---: | ---: |
| 一个 dense float32 `[Q,Q]` 邻接 | 约1.172 GiB | 约3.43 MiB |
| 一个 float32 `[Q,128]` 题目参数 | 约8.66 MiB | 约0.463 MiB |

真实稀疏图应按 nnz 计算，COO 索引本身也占空间；若加载的是 dense 文件，先 `.to(device)` 再 `.to_sparse()` 还可能出现转换峰值。题图可能因共享 KC 而边数很多，不能仅按小参数矩阵估算16GB显存是否足够。

每次 forward 都对**全部 Q/C 节点**跑 GCN，之后才查本 batch 的 ID；没有仅抽当前题目的子图。图代价约为 `L*((Q+C)*d²+(Eqq+Ekk)*d)`，还叠加约 `B*T*d²` 的顺序 GRU；源码每步调用一次 GRU，共享逐目标重放会反复运行全图。KG 构建、实际 nnz、embedding dtype、ROCm sparse backward、完整共享验证成本均未实测；不能从核心导入成功推断训练或预算通过。

另一个忠实性细节：题目 `self.change` 与 KC `bert_projection` 在构造时输出被包成新的 `nn.Parameter`，之后训练前向直接用这些节点参数；其初始化投影不沿原图持续反传。后续梯度检查应核对实际使用参数，不要求每个已注册初始化投影都产生梯度，也不静默“修复”为新的端到端语义编码方法。

## 最小接入顺序与放行边界

1. **先补资产来源和信息条件，暂不跑真实模型。** 固定作者 notebook/文件版本，列清论文实际三集；审计图、SBM、文本及 map 的 train/catalog 信息边界与许可证。明确1024维 KC 向量的原始文本、编码模型、预训练来源及其相对 B003 的额外信息，未核实前不视作同输入。若确认使用外部文本/预训练内容，预先选择内容增强轨或给 baseline 同等信息；去文本版本另列变体，不能沿用“原 CGMKT 同输入比较”的称谓。验证当前 prepared Q/C ID 映射；原资产不对齐时必须可复现重建，不能只检查维度相同。
2. **独立 wrapper 与资产清单。** 固定三份模型源码哈希，使用隔离 namespace 绑定设备和路径；处理 `cgmkt.py` 顶层 `sys.path.append` 的全局影响。单独接受 `num_q,num_c,emb_size` 配置，不能套现有 Transformer builder 的 `n_question,n_pid,d_model` 接口。题图/KC 图是普通 tensor 属性，不随普通 `.to()` 自动迁移、也不进入 `state_dict`；Q_hat/transition 才是 buffer。checkpoint 必须额外绑定全套外部资产、预处理、映射与实际 fallback 身份。
3. **人工资产、CPU 优先的最小接口验证。** 用小型人工图和向量检验题/KC shape、batch1、multi-KC pooling、mask/shift、右 padding、CPU/GPU设备迁移、checkpoint reload、同一模型初始验证后再训练的兼容性。目标回答/未来响应扰动不变，允许历史响应扰动应能改变预测；历史外状态不得沿用。当前卡没有执行这些检查。
4. **来源与比较信息条件闭环后优先 NIPS34，再 AS09。** 后续真实训练入口保留题目级输入和原 BCE；v2 验证消费同一 `SharedEventDataset` 历史/查询，严格 epoch0+每轮最佳 AUC 选点、最多50轮/patience3、单独量预算。相同目标和历史只能证明事件层面的配对，不能抵消文本向量带来的额外内容；报告须同时标明内容增强、同等信息对照或去文本变体的身份。可用 d128/batch32 作为有标注的本项目固定预算起点，但不得叫作者最佳配置；图 nnz 与完整验证耗时合格后再扩展。
5. **AS15 暂列不支持。** 任何 KC-as-item、删除题图、造题号或改用单一 dummy 的方案都会改变问题表示/结构，必须另列消融或变体，不能补一个名字就算三集 CGMKT 复现。

没有论文全文与图生成者，当前可以完成的是“接口/因果依赖静态审查”，不是论文性能复现。显式 group mastery 和用 mastery 调制交互的思想已有此近邻方法；其接入缺口不能被当作原创空白，后续本项目若提出状态更新机制，仍应解释与 CGMKT 的差异并在可复现条件满足后纳入对应比较。
