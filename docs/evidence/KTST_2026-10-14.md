需要纠正的概括：

- **“官方 AS09 用6层 decoder”只对 mean 的 fold0 代表配置成立。** mean 五折是 `[6,5,8,5,5]`；MHSA 则是 `[7,8,8,7,7]`。
- **“官方 AS15 用 d256”只对 mean 的 fold0、1、3、4 成立。** fold2 是 d128。不能把前述 d256 代表配置当成五折共享固定配置。
- 先前 vendor 中的 NIPS34 `reproduce_50` 是 **fold4 / seed57**，不是 B003 的 fold0。真正同折参考是 `reproduce_29`，其 encoder4 / decoder4。
- 固定 benchmark 目录中没有 AS15 / NIPS34 的 MHSA 复现配置；与论文未报告对应成绩一致。不要人为把 mean 配置换一个 aggregation 后称为该数据集“作者最佳 MHSA”。

三类表示也不能混淆：mean 是 `set_dense + q_mean_c`，MHSA 是 `set_dense + self_attn_all`；`combinatorial_dense + q_mean_c` 对应 unique set 变体。对于 mean，YAML 中 `nhead_agg` / `num_layers_agg` 不生成 MHSA 聚合层；源码只在 `self_attn_all` 分支使用它们。因此不能把 mean YAML 中的 `num_layers_agg: 2` 算成两层额外 Transformer。[模型构造分支](https://github.com/kainbr/kt_set_transformers/blob/e6331a6f45e597f286d1272fbb96e7bb67bcaa52/pkg/model/KTST.py#L81-L102)

## 3. 官方训练、搜索与 seed

固定提交的 benchmark 搜索空间写明：d ∈ {128,256}；Transformer heads ∈ {4,8}；encoder ∈ {1,…,6}；**decoder ∈ {3,…,8}，不包含2**；FFN ∈ {256,512}；dropout ∈ {0.05,0.10,0.15,0.20,0.25}；classifier ∈ {128,256}；学习率 ∈ {5e-5,1e-4}；weight decay ∈ {1e-5,5e-5}。benchmark batch size 固定128；MHSA 聚合 heads=4、layers=2。Optuna `n_trials=100`、sampler seed=7；模型运行 seed 使用 Hydra job number，再由复现 YAML 保存各折实际 seed。[search_space.yaml](https://github.com/kainbr/kt_set_transformers/blob/e6331a6f45e597f286d1272fbb96e7bb67bcaa52/pkg/config/sweep/ktst/search_space.yaml)

mean / MHSA 两个搜索入口分别固定相应 aggregation 和 `learnable_alibi_monotonic_q_k`，θ 学习率候选都是 {1e-4,5e-4,1e-3}。[mean 搜索](https://github.com/kainbr/kt_set_transformers/blob/e6331a6f45e597f286d1272fbb96e7bb67bcaa52/pkg/config/sweep/ktst/benchmark_mean.yaml) · [MHSA 搜索](https://github.com/kainbr/kt_set_transformers/blob/e6331a6f45e597f286d1272fbb96e7bb67bcaa52/pkg/config/sweep/ktst/benchmark_mhsa.yaml)

本卡核查的20个 mean / MHSA 复现 YAML 均为最多200 epoch、early stopping tolerance=10、梯度裁剪1、训练 batch128、验证 batch64。官方 trainer 在更新前先验证和保存初始候选，随后每轮验证；仅当验证 AUC **严格增加**时重置计数并保存，10轮未改善停止。并非强制跑满200轮，也不是按测试 AUC 选 epoch。[Trainer.run / log_results](https://github.com/kainbr/kt_set_transformers/blob/e6331a6f45e597f286d1272fbb96e7bb67bcaa52/pkg/logic/trainer.py#L69-L92) · [严格改善条件](https://github.com/kainbr/kt_set_transformers/blob/e6331a6f45e597f286d1272fbb96e7bb67bcaa52/pkg/logic/trainer.py#L209-L227)

优化器为 Adam；参数名以 `thetas` 结尾的 ALiBi 参数使用单独 θ 学习率，其余参数用主学习率。训练前的数据初始化、模型初始化都调用配置指定的 seed。**上述逐折不同 seed 不能重写成同一配置的多 seed 重复实验**，也不能把配置中的 seed33、78、53替换成42后继续称为完全相同的复现。[官方 train.py](https://github.com/kainbr/kt_set_transformers/blob/e6331a6f45e597f286d1272fbb96e7bb67bcaa52/train.py#L45-L88)

固定 trainer 另有已确认的执行缺陷：`y_pred_pre_q` 只在 flat 分支赋值，却在 set_dense 路径也被使用。这里记录的是官方代码意图及配置证据，不声称该提交的整个原 trainer 可直接运行。本项目包装器绕过该 trainer；数学模型保留官方实现。[缺陷位置](https://github.com/kainbr/kt_set_transformers/blob/e6331a6f45e597f286d1272fbb96e7bb67bcaa52/pkg/logic/trainer.py#L150-L187) · [本项目接入说明](../KTST_INTEGRATION.md)

## 4. 官方修正 window 与 B003 共同历史不是同一产物

官方数据类从 `train_valid_sequences.csv` 按 fold 取训练/验证。其上游先做最多200个 KC 位置的分块，再用 `is_repeat` 合并同次作答；块首若是 continuation，会成为新片段。组内 KC 使用 `list(set(...))` 去重，因此训练/验证边界可能保留一个题目的部分 KC。验证排除每段首事件。[官方训练/验证数据入口及转换](https://github.com/kainbr/kt_set_transformers/blob/e6331a6f45e597f286d1272fbb96e7bb67bcaa52/pkg/data/pykt/__init__.py)

官方 `preprocess.py` 明确重写 `test_window_sequences_quelevel.csv`：按整题 KC 数累计，窗口中包含当前题在内的 KC 数不超过 `max_len=200`，超限时从左侧移走整题。首个窗口选多个位置，后续窗口只选最后一题；评测端再把每窗首位 mask 置为不计分。它不是“200道题历史”，也不是 pyKT 原非滑窗 question 文件。本次只查看生成及读取源码，**没有运行预处理、读取本项目 test 记录或评测 test**。[窗口修正代码](https://github.com/kainbr/kt_set_transformers/blob/e6331a6f45e597f286d1272fbb96e7bb67bcaa52/preprocess.py#L161-L228) · [set_dense 评测 mask](https://github.com/kainbr/kt_set_transformers/blob/e6331a6f45e597f286d1272fbb96e7bb67bcaa52/pkg/data/pykt/eval_dataset_format_set_dense.py#L89-L121)

B003 的 `ktlab-v2-shared-event-context-kc200-dev` 则从完整开发集 `train_valid.csv` 恢复事件，KC 按原出现顺序去重，为每个目标取此前**最长连续完整事件后缀**，满足“历史 KC + 当前题全部 KC ≤ 200”且至少有一历史事件；相同题号的不同作答保留不同 event ID。当前答案只给指标，不进入 query。所有模型共享这些目标和允许历史，但用各自表示预测。这是本项目新开发协议；即使预算数字同为200，也不能省略目标/历史的逐项等价证明而视为论文官方评测。[本项目共享协议](../SHARED_EVENT_PROTOCOL.md) · [实现](../../src/ktlab/shared_events.py)

## 5. B003 与作者配置的具体差异

本节依据当前 [B003 manifest](../../configs/batches/B003-shared-convergence-baselines.json)，canonical SHA256 为 `765c4d0183fd0b4332d50f6b6f7a206c845e007fb06fa87a640bf286e5e80d44`，源码摘要仍为 `e865cf930845b50d12bcad4afbd02a39e18e67bbcf7dc57ad9dbc1038a9dc1cb`。历史方案快照 `a9d2958f306adb2177e7da39246d668791a4c3145b8f1ca2351228d5344262dc` 的200轮/耐心10设置未执行，已被当前50轮/耐心3版本替代；本卡补记状态，不新增训练结果。

## 6. 可支持的结论与仍缺证据

可以引用：作者 Table 1/6 的上述 AUC；固定提交中逐折参数；官方搜索和窗口代码；本项目 B003 与其明确不同的配置及验证语义。

不能据此推断：本项目已经复现作者 AUC；AS15/NIPS34 存在已报告的 MHSA 数字；AS09 一律6decoder或AS15一律d256；单折seed42足以代表五折统计；B003 验证分数高于论文数字就说明超过论文或当前 SOTA。若要做“作者设置复现”，需要另行冻结对应逐折配置、数据及评测产物、运行修正说明和统计口径；本卡没有创建该训练批次。
