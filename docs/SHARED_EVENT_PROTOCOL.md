# 共享题目事件与历史的开发评测协议

日期：2026-10-14。协议标识：`ktlab-v2-shared-event-context-kc200-dev`。本轮在 `research/shared-event-protocol` 分支实现开发集评测接口；该协议开发工作不训练、不解封测试、不修改冻结的 main/B001。既有批次（包括 B002）的批准范围不包含本协议变更；新源码不能沿用旧批次的源码摘要启动训练。

本协议解决一个具体问题：同一学生、同一目标题，模型是否使用了**相同的允许历史和题目信息**。它不规定模型必须采用相同内部表示，不自动消除训练目标、参数量和优化预算差异，也不代表已复现论文成绩或达到 SOTA。与原 v1、KTST 参考开发轨的差异必须保留；不能把旧结果或 checkpoint 直接改名。

## 1. 范围和接口合同

当前支持 ASSIST2009、ASSIST2015、NIPS34；复用已冻结的学生划分与 ID 映射，只读取开发集 `train_valid.csv`。`SharedEventDataset(manifest, fold, split="valid", kc_budget=200, max_targets=None)` 只允许 `train/valid`，`test` 必须在读取其记录前失败。实际处理文件必须与 manifest 的大小、SHA256一致。

`kc_budget` 固定为200；不允许参数改成别的值却保留 `kc200` 协议名。`max_targets` 只用于开发调试，选择规则为确定性前缀，不根据答案、预测或模型能否处理选择目标；审计必须区分全 split 的合格目标数与实际选取数，显式标记限量。限量检查不能写成全量评测。

核心职责如下；实现与验收结果须对应同一源码摘要：

| 接口 | 允许的职责 | 不承担的职责 |
| --- | --- | --- |
| `shared_events.SharedEventDataset` | 恢复源事件、选目标和完整历史、生成稳定键和摘要 | 不调用模型、不访问测试、不生成训练统计特征 |
| `shared_adapters.collate_shared_kc` | 相同历史展开为 AKT/simpleKT/MoC-KT 的逐目标 KC 输入 | 不自行重选历史、不补前一窗口、不使用目标答案 |
| `shared_adapters.collate_shared_ktst` | 同一历史合并为 KTST 原生事件输入 | 不 late-mean 冒充 KTST、不复用旧分块的 partial set |
| `shared_adapters.predict_shared` | 无梯度输出每个目标题的一个概率 | 不提供可训练 loss、不负责批准或选择 checkpoint |
| `shared_adapters.audit_shared_projection` | 解码实际张量，核对允许历史和查询 | 不只依赖两条路径携带相同 hash 就判通过 |

这些接口是新的开发评测路径，不隐式切换原 `engine/evaluation` 的协议。可运行的接口和前向检查不等于已经具备该协议下的训练结果。

## 2. 从 KC 行恢复真实作答事件

事件身份使用 dataset、uid 和学生原始事件序号，不使用题号作为事件身份。只有 `is_repeat` 标记属于同次作答的 KC 行才能合并；同题号连续出现且 `is_repeat=0` 时仍是两次独立作答。合并组内题号、答案必须一致，否则整份输入审计失败。

每事件的 KC 按首次出现顺序去重，即保留 `dict.fromkeys` 对整数 KC 的顺序。预算按**去重后 KC 数**计算，两个投影使用相同去重结果；不能一个路径按重复行数计时、另一个按集合大小计时。本规则有意不同于 KTST 参考轨的 `list(set(...))`，也不同于保留重复行的 v1，因此单列新协议。报告原 KC 数、去重移除数和最终集合规模。

ASSIST2015 没有真实 question ID，canonical event/query 中题号为 null，每条原始记录是独立事件。KTST 的 q=0 常量占位、KC 模型的无独立题分支属于适配约定；不把占位值解释为真实题目，也不据此报告题目冷启动或题目长尾收益。

回答只能是0/1；非法标签或组内矛盾作为数据完整性错误拒绝，不是按难度/正确率筛选样本。对合法0/1值而言，目标是否入选和其窗口边界不依赖当前答案。

## 3. 唯一的共同历史定义

设第 t 个目标事件去重后的 KC 集合为 `C_t`，此前事件为 `e_0 ... e_(t-1)`。历史 `H_t` 是满足下面条件的**最长连续完整事件后缀**：

```
sum(len(C_j) for e_j in H_t) + len(C_t) <= 200
```

构造从最近事件向前进行；加入下一个更早事件将超预算时立即停止。禁止跳过装不下的近期事件，再找更远的小事件填满预算。禁止截掉某事件的部分 KC，也禁止为当前题的不同 KC 分别放宽历史。

评分资格及排除顺序固定：

1. 当前题 `len(C_t)>200`：排除，记为 `target_over_budget`。
2. 否则按上式取后缀；没有至少一个完整历史事件：排除，记为 `no_history`。第一事件自然属于这一类；当前题恰占200 KC时也无法留下历史。
3. 其余目标入选，每个源作答事件只产生一个最终计分概率。目标选择不看当前回答、未来回答、未来序列总长或模型预测。

例如，当前题有198个 KC，最近历史题有1个 KC，再前一题有2个 KC，则只能保留最近那题，总预算199；不能拆前一题取1个 KC 来凑满200。若最近题已经无法放入剩余预算，历史为空，即使更远处有小题也不能跳过最近题。

目标预算包含当前题**全部** KC。KC 模型每次只预测其中一个 KC，实际输入位置数可能少于该预算；它不能利用空出来的位置获得额外历史。KTST 的实际事件数也可能远小于展开位置数。这是相同允许信息的不同编码，不是相同张量长度或相同计算量。

## 4. 模型实际看到什么

每个上下文对象将 `history`、`query` 与 `label` 分开：历史元素包含事件键、题号、KC、已观察回答；query 只有当前题号和 KC；label 只供外部指标消费。修改 label 不得改变模型输入张量、目标资格或当前窗口。

| 模型路径 | 实际输入 | 最终计分方式 |
| --- | --- | --- |
| AKT/simpleKT | 同一 `H_t` 按 canonical KC 顺序展开，每条过去 KC 携带该过去事件回答；末尾只加当前一个 KC | 对当前题每个唯一 KC 分别预测，完整精度算术平均 |
| MoC-KT | 与上述 KC 路径相同；`ground_seq=展开历史 KC 数+1` | 同题各 KC 使用相同历史、相同长度组，最后再聚合 |
| KTST mean/MHSA | 每个完整历史事件一个集合位置；末尾是完整当前题集合 | 直接取当前事件原生概率，不做 KC late mean |

输入答案槽的当前值固定为 dummy 0，真正 label 不传入预测张量。模型本身还须通过当前答案扰动的因果检查，不能仅靠“当前数据碰巧为0”掩盖模型取了当前答案的错误。AKT/MoC 使用原始 full 输入和明确目标位置；simpleKT 仅按原接口构造一次 shift；KTST 保留模型内部历史移位。不得为了对齐输出再多移一格，误取前一题概率。

KTST 原 `forward` 会计算包含历史和 dummy 目标的 loss。共享预测接口必须丢弃它，不对外称为目标的真实 loss，也不能拿它训练。调用只传符合原语义的 data/padding_mask；只给最后查询计分是外层索引，不把 last-only score_mask 塞入要求“全部非首有效事件”的参考轨 wrapper。共享预测接口使用 inference mode 和 eval mode，无 backward、optimizer 或模型参数更新。

MoC-KT 尤其需要明确：固定 `[B,200]` padding 长度、原学生最终序列长度、截窗前已经发生的累计历史长度，都不能替代当前可见前缀长度。其上游卷积分组在50/150位置设阈值；传入未来最终长度会让过去预测依赖未来序列是否继续，传入200 padding长度会把短历史错误放进长组。当前协议选择本次窗口内 `history_kc_count+1`，属于明确的新评测语义，不宣称等同于上游整段训练长度语义。[上游 MoC-KT 固定源码](https://github.com/pykt-team/pykt-toolkit/blob/eec087e0230520e7ae7bbd4f5433d71612df62fb/pykt/models/mockt.py)

本轮同信息比较不增加真实时间、题目文本、选项、全数据难度/频次等特征。需要这些信息的模型应单列条件，不为了接入而伪造字段。

## 5. 摘要、实际投影审计和指标

每个目标分别保存 target/context 摘要。target 摘要包括源事件身份与 query；context 摘要还包括**有序**历史事件身份、题号、KC及允许回答。当前 label 不进入二者。源文件 SHA256 则覆盖全部文件字节，修改任意答案后源摘要仍应改变，二者作用不能混淆。

摘要采用明确的域标识、规范 JSON 和有序组合，审计记录实际 scheme/hash scope。完整 split 摘要与 `max_targets` 选择后的摘要/数量要区分。改变某事件答案，不改变它自己的 target/context 摘要；当它成为后续目标的允许历史时，后续 context 摘要应改变。

数据集建立索引时校验源文件，评测开始和结束时再次核对源摘要，并在输出过程中重算完整所选目标/context序列摘要，与冻结清单逐项相符后才落盘。只重算单个上下文摘要再与它自己携带的摘要比较是不够的：源文件改变后，二者可能同时改变。尤其最后目标的 label 不进入任何 context 摘要，必须靠源字节摘要捕获。按行重新读取源数据时还应校验该学生记录未变。

相同摘要只证明引用同一合同。投影审计还必须从实际 tensor 读回每个历史事件/展开 KC 的题号、答案、顺序、padding、当前位置与答案占位，并与 canonical context 逐项比较。KTST 必须逐事件检查边界；仅 flatten 后相同会漏掉“相同题号/回答的相邻事件之间挪动 KC”这一错误。所有模型必须有相同目标键集合和允许历史，不能在得到预测后才取能成功输出的交集。任一目标丢失、重复、缺 KC、NaN/Inf或概率越界时失败，不跳过坏样本继续给好看的指标；每个 KC 概率在求均值前即检查范围，不能让负值和大于1的值相互抵消。

每个事件只计算一次 ROC-AUC、ACC、NLL、Brier、固定15分箱 ECE。KC 聚合使用 float64 算术平均，不取最大值、不平均 logits、不沿用四位小数截断。缺少任一目标 KC 时不能报告部分均值。汇总和未来配对 bootstrap 以原事件键对齐，不以张量行号对齐。

后续正式统计仍按每个 run 独立计算 AUC，再比较匹配 run 的差值；不得先跨 fold/seed 平均预测而意外变成集成。当前协议没有最终测试分数、置信区间或胜出结论。

## 6. 可检验的验收清单

下面是必须核验的断言。测试和全量审计输出是证据，本文不预先把尚未执行的项目标为通过。

| 检查 | 输入变化或边界 | 必须观察到的结果 |
| --- | --- | --- |
| 学生/测试隔离 | train/valid不同fold；请求test | 无学生交叉；test在读取测试记录前拒绝；实际读文件白名单只有开发源文件 |
| 真实重复作答 | 连续相同qid，分别用is_repeat 1/0 | 前者组内合并，后者保留新事件；q/r组内冲突明确失败 |
| KC去重 | 组内 KC `[2,2,1]` | canonical 为`[2,1]`；预算/两个投影均只含一次2；移除计数增加1 |
| 200预算边界 | 当前198、最近1、再前2 KC；当前201 KC | 前者只保留最近事件；后者只记target_over_budget；所有历史事件完整 |
| 连续后缀 | 最近事件放不下、更早事件能放下 | 不跳过近期事件，目标因无历史排除 |
| 当前标签独立 | 将一个合法目标0翻成1 | 该目标资格、query/history、两个摘要、实际输入及预测不变；外部指标使用新标签 |
| 历史标签可见 | 修改允许历史中一题答案 | 投影对应历史答案改变，context摘要改变；不强求随机未训练模型概率必变 |
| 未来不可见 | 在目标后添加/删除/改变事件，使源总长跨50/150 | 已存在目标的窗口、MoC length group、输入和预测不变 |
| MoC阈值 | 实际展开前缀长50/51/150/151，padding仍200 | ground_seq分别为50/51/150/151；组别按原阈值，不能全部变成200 |
| 同题同历史 | 当前题多个唯一KC | 每个KC输入的全部历史相同；只允许末尾当前KC不同；KTST历史解码完全相同 |
| 末位/shape | 最短合格上下文、一条batch、混合长短batch | 每目标恰取其当前位置概率；无双重shift、广播掩盖或batch1维度丢失 |
| 聚合完整性 | 任意打乱目标KC请求顺序、改变推理microbatch大小 | 事件均值在容差内不变；缺失/重复KC直接失败，不部分融合 |
| 集合顺序 | 置换同题KC | KTST原生集合预测在容差内不变；KC模型历史内部顺序敏感性单独披露，不能假称所有架构均集合不变 |
| 数值与设备 | CPU及可用ROCm的相同无梯度fixture | 概率有限且在[0,1]；已声明容差内一致；数据保留CPU、仅batch搬运 |
| 旧checkpoint边界 | 用v1/KTST-reference的既有权重做开发诊断 | 不修改原checkpoint协议/metadata，不标成按共享验证选出的正式候选 |

数据审计还需给出按数据集/fold/split统计的源事件数、去重数、合格目标数、no_history/target_over_budget数、历史KC/事件长度范围和分布、target/context摘要。全量结构审计不要求先运行全量模型；几个无梯度样例通过不能替代全量目标/历史审计。

## 7. 何时可以建立正式共同排名

本轮完成的条件是：开发源数据的目标/历史合同可重复，至少两类实际投影可审计，答案/长度泄漏与边界用例通过，测试入口关闭。输出应标明无梯度诊断/结构审计，不把随机权重或旧协议权重的分数写进强基线表。

正式比较还需要新的具体批次：冻结本协议及摘要，声明各模型训练表示/目标、超参搜索和预算，**用同一共享验证目标选择各自 checkpoint**，再冻结候选和统计方案。可以保留各模型原训练表示，但必须承认 loss 单元和训练/评测差异，并在研究结论中区分架构与协议贡献。旧 v1 checkpoint 只能用于另标的迁移诊断，不能重标为共享协议训练成果。

最终测试的事件构造、权限和独立解封仍是后续工作；不能为了比较而用开发接口接受test，也不能看过测试结果再改窗口、去重、目标选择或候选模型。所有梯度更新和最终测试继续单独申请批准。本协议建立公平比较的必要输入条件，不是对结果领先的承诺。
