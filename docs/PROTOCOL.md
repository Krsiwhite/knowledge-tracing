# 三数据集统一评测协议

版本：v0.1，2026-10-14。适用：ASSISTments2009、ASSISTments2015、NIPS34。

本协议用于本项目内部的公平比较。它采用固定学生test、统一验证/测试语义和明确的checkpoint选择规则；结果中的协议标识固定为 **ktlab-v1-causal-valid-full-precision-repeat-kc-train**，与训练引擎一致，不能直接写成原论文精确复现或全领域SOTA。当前没有已完成的梯度训练或最终测试结果。

## 1. 数据版本、划分和共同输入

- 原始文件只读保存；记录下载来源、访问日期、许可/访问条件、SHA256和预处理代码提交。处理后保存学生/交互/题目/KC数量、过滤计数和ID映射；不把数据或模型权重提交Git。
- 一次固定按学生80%/20%划分开发集和test，split seed=1024，与固定pyKT预处理版本一致。开发集再做学生级5-fold：每fold约64%总学生训练、16%验证、20%固定测试。不同模型和训练seed复用相同学生清单；训练seed不重新划分数据。
- 若采用pyKT已发布划分，首先验证它满足上述比例和学生隔离，并保存学生清单及文件摘要；不在不同模型间混用重新划分和原发布划分。无法确认时暂停该数据集的比较并记录原因。
- 验证/测试的共同输入为历史题ID（存在时）、KC集合及过去的二元回答。当前目标题ID/KC可见，当前及未来的回答不可见。训练保留上游展开语义，差异见下节。额外文本、选项、时间和预训练特征须单独标明并设同信息基线。
- AS2015缺少独立题ID时使用其真实可用的KC表示，不构造虚拟题目ID；adapter的占位值不被解释为真实题目。该数据集不用于声称题目冷启动或题目频次建模的效果。AS09的排序字段不是默认真实时间间隔。
- 当前FA-KT adapter要求真实timestamps，不能用序号伪造时间。缺失时间的数据集不进入FA-KT共同信息比较；使用时间特征时单列信息条件，并与获得相同时间信息的基线比较。
- 所有频次、正确率、难度统计、交互学习图及归一化参数只在当前fold训练数据拟合。题库本身公开的静态KC关联若使用全题库，需显式登记，且不能混称严格归纳cold-item协议。

## 2. 序列、题目事件与标签可见性

训练最大序列长度为200，保持学生内原始事件顺序，按固定pyKT预处理规则切片；不足长度使用padding，最短有效序列长度为3。当前长度单位是展开后的KC位置，含目标位置，不能解释为200个完整题目事件。

为保持已有训练管线的可追溯性，基础复现阶段保留并记录上游训练中的多KC展开及历史重复KC语义。**这不意味着验证/测试可以看到同题另一展开行的答案。** 同一原始题目作答事件必须有稳定event ID；真正的再次作答有新的event ID。不能仅凭相同题ID把多次作答合并。

验证和测试统一遵守：

1. 对同一个原始作答事件的所有KC预测时，历史只包含该事件之前已完成的事件；当前事件答案对所有KC均不可见。
2. 对多KC预测概率以完整精度取算术平均，得到该事件的一个正确概率；每个事件只计一次指标。标记为late_mean_full_precision，有意区别于上游部分四位小数聚合。只有KC级标签而不存在多KC展开的事件直接使用其预测。
3. 当前目标的同题兄弟KC行及答案不进入其历史；更早事件仍保留展开后的重复KC历史。安全展开不是“每道题只更新一次”的新架构。历史里的过去答案可见，当前答案对所有同题预测不可见。
4. validation与test使用同一安全展开规则及聚合器；AS09/NIPS34调用固定上游generate_question_sequences，window=False、maxlen=200、min_seq_len=3。切片第一位置不作为下一步目标，短尾段按上游规则排除；记录最终选择事件集合。AS2015使用原始单KC序列并遵守同样的shift/mask规则。

默认确认比较使用相同的200个展开位置切片策略，不默认把前一切片的全部历史带入下一切片。先移除当前目标的同题兄弟，再切片；较早历史事件可以在边界截断，这会影响可见上下文，但不能使当前答案进入历史。若某模型原文要求完整历史、最后50/100次或专用窗口，保留为独立paper-protocol记录，不把其分数直接并入统一表。

保存每条预测的student/event ID、真实题ID（存在时）、KC数量和有效mask。所有比较模型必须评测相同目标事件集合；同一目标的KC不完整或重复时拒绝输出部分融合结果。文件已生成只说明预处理完成，还需要检查通过才能用于训练比较。

训练保留展开语义而评测使用整题语义，会产生训练/评测差异，应作为已知限制记录。事件原生训练可成为后续明确的消融或共同协议升级；升级后全部主比较模型需使用同一版本，不能只修改新模型的数据表示后隐去差异。

## 3. 训练、模型选择与运行记录

- 数据文件保留在本地磁盘，Dataset按需从CPU侧读取；每次只把当前batch移到计算设备，不在Dataset初始化时把整个数据集送入GPU。CPU设备绑定只作用于本项目隔离加载的上游namespace，不修改共享安装包或其他项目的全局设备设置。记录实际设备、精度、依赖版本、峰值显存与耗时。
- checkpoint只依据**事件级validation AUC**选择。出现更高值时保存当时的真实模型权重、模型配置、epoch和验证指标；不得保存对后续训练继续变化的引用，也不得误用最后一轮权重。当前最佳模型checkpoint不等于可无损断点续训checkpoint；若后续支持resume，需另存优化器和随机状态。
- test不能用于选择epoch、超参数、模型、阈值或场景。筛选阶段的训练入口不得自动读取test指标；最终test前冻结配置和checkpoint摘要。
- AUC相同则保留较早checkpoint；无有效双类别validation、NaN/Inf、无有效mask、样本集合不一致或没有有效checkpoint均判为失败，不回退到test选择或报告0分。
- baseline和新模型使用相同输入、学生划分、评价目标和已批准预算。若搜索次数、参数量、epoch上限或计算量不同，必须显式列出。没有批准的训练预算时不启动训练。
- 训练seed固定为42、2026、3407；记录随机种子和确定性设置。随机性仍可能受硬件/算子影响，不宣称跨硬件逐位一致。当前不支持中断续训；加入该能力时需另外保存完整随机状态及优化器状态。
- 一次运行至少记录：run ID、批准批次ID、Git提交与未提交差异摘要、数据/划分摘要、完整配置、fold/seed、开始结束时间、设备、最佳epoch、validation指标、退出状态与checkpoint路径。

## 4. 筛选、最终确认与统计解释

主指标为事件级ROC-AUC，辅助指标为ACC（固定阈值0.5）、NLL、Brier和15个等宽分箱的ECE。概率裁剪规则只用于NLL数值稳定，并在所有模型中一致。校准分箱已固定；短历史阈值和长尾定义必须在最终test前固定，不按测试结果修改。

筛选主要看validation上的配对AUC差值。绝对提高0.003等于0.3个百分点；这是一项预算与路线讨论的触发值，不是必须兑现的结果承诺。达到时优先讨论整体AUC主线的完整确认；未达到时检查方差、成本及困难场景证据，与用户决定继续整体优化、转向场景或延长时间。困难场景路线必须经用户在test前登记数据集、场景定义、主指标、比较对象与成功条件。探索性子集不能事后包装为预注册结论。

最终预算为冻结新模型和每数据集通过validation选出的最强基线，各5-fold×3-seed。报告15次结果的均值、标准差及逐run配对差值，不挑选最好seed/fold，也不把fold间重叠训练集当作15个独立样本。默认不做模型集成；集成另列实验。

最终统计方案在该批次申请中确认：默认采用相同test学生的配对cluster bootstrap（2000次、bootstrap seed=42），每次抽学生并保留其完整事件；同一学生的重采样次数在两个模型和全部匹配seed/fold之间共享。每个冻结run分别计算AUC差值后取run均值，不能先平均预测概率而变成集成模型。`ktlab.statistics.paired_auc_bootstrap`要求完整的seed×fold网格、相同测试事件/标签，拒绝重复或不匹配记录，并报告逐seed均值方向和描述性区间。这是**给定已训练模型的测试学生抽样区间**，不是重新训练模型的不确定性；3个训练seed也不是3份独立测试学生样本。AUC无定义的单类别重采样会重抽并记录次数，尝试数有上限，区间条件于抽到两类标签。

默认三个数据集共同构成预登记主比较家族：调用`confidence=0.95, family_size=3`，每个区间使用双侧alpha=0.05/3（即98.333…%置信水平）的Bonferroni调整；输出同时记录family alpha、单比较alpha与家族大小。这是对百分位bootstrap区间的调整，覆盖率依赖bootstrap近似，不称为精确有限样本保证。也可在批准批次中事先登记一个主要数据集。逐seed区间只作稳定性诊断，不额外宣称显著性。`holm_adjust`仅供已有有效原始p值的预登记比较家族使用；不能把百分位区间、bootstrap正差比例或重复seed当作原始p值，当前模块不自动生成p值。当前只有合成数据验证，没有实际训练结果或模型胜出结论。

“显著提高”要求预先登记的比较差值为正且相应区间下界大于0；0.3个百分点的探索门槛不能替代该判断。无显著差异、存在退步、或只在一个场景有效都如实报告。已结束的最终测试不无故重复运行。

## 5. 每批训练的批准门槛

这里的“训练批次”指一次提交给用户的实验运行清单，不是训练循环中的每个mini-batch。所有会计算梯度/更新参数的工作，包括训练烟测、超参搜索、消融、额外seed/fold和反向兼容性检查，均须先有用户明确批准。

每批申请包含：研究问题、模型与配置、数据版本、fold/seed、最大轮数或时长、预计资源、checkpoint规则、产物、终止条件以及是否接触最终test。批准仅覆盖列出的工作；失败后调整模型/预算或扩大范围需重新对齐。只读代码审计、下载/预处理、数据完整性检查和无梯度前向检查可以在既有授权内推进。

本地RX9070XT 16GB优先。付费API、云GPU、额外数据访问条款或需要改变资源安排时先对齐，不凭研究目标推定费用授权。

首批拟申请的训练烟测：AS2015上的AKT和simpleKT各5次optimizer更新，总预算上限30分钟，只验证训练链路和validation/checkpoint机制，不接触最终test。此处是待批准方案，**不表示已获批准或已有训练结果**。

## 6. 必须通过的检查

| 检查 | 通过条件 |
| --- | --- |
| 学生隔离与数据映射 | train/valid/test学生不交叉；fold清单与摘要可重复；题/KC/回答合法，padding有独立mask。 |
| 同题多KC泄漏 | 修改当前事件答案不改变当前事件任何KC的预测；只允许影响后续事件。 |
| 未来泄漏 | 修改未来回答不改变此前预测；未来统计量不进入特征或图。 |
| 事件聚合 | 多KC只产生一个计分事件；真实再次作答保留；切片边界、padding和滑窗不漏算/重算。 |
| 验证/测试一致性 | 同一输入和checkpoint下两条路径的事件概率、mask和聚合一致。 |
| checkpoint真实性 | 人为构造“中途最好、最后变差”的验证轨迹，确认加载的是中途保存权重；测试数据未参与选择。 |
| 资源可行性 | 数据常驻CPU、batch按需移动；无梯度检查先通过；批准后才进行反向检查及短训练。 |
| 指标与统计 | 固定小样本的AUC/ACC/NLL/Brier与独立计算一致；bootstrap以学生为单位并配对同一事件集合。 |

任何检查失败时先修正并留下版本差异，再申请对应训练。检查通过说明评估机制可信，不说明模型已经优于SOTA。
